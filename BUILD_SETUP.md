## Quick Start Workflow

### 1. Build Locally
```bash
npm run build
```
Generates `client/dist/` folder

### 2. Test Locally
```bash
npm run build:prod
```
Starts Express server serving the build at http://localhost:3000

### 3. Commit & Push to GitHub
```bash
git add -A
git commit -m "Build: production React build"
git push origin main
```

### 4. Deploy on CityHosting
```bash
cd /var/www/kotopes
git pull origin main
npm install
NODE_ENV=production PORT=3000 node server/index.js
```

Or with PM2 (recommended):
```bash
pm2 start server/index.js --name "kotopes" \
  --env NODE_ENV=production \
  --env PORT=3000
```

## Architecture Flow

### Development
```
Browser :5173 (Vite)
    ↓
Vite Dev Server (hot reload)
    ↓ /api, /images requests
Express :3000 (backend)
```

### Production
```
Browser :80 or :443 (HTTPS)
    ↓ (via Nginx reverse proxy)
Express :3000 (serves React build + API)
    ↓
client/dist/index.html
    ↓ API calls
/api/* endpoints
```

## Environment Variables for Production

Set these on CityHosting server:

```bash
NODE_ENV=production        # Enables build serving and SPA fallback
PORT=3000                  # Server port (or any available port)
```

Optional:
```bash
LOG_LEVEL=info
CORS_ORIGIN=*             # If needed for external API calls
```

## Important Notes

- The `client/dist/` folder is checked into git (unlike typical SPA deployments)
- This allows simple `git pull` deployment without needing build tools on server
- If you prefer server-side builds instead, see "Alternative: CI/CD" in DEPLOYMENT.md
- Static assets (images) are still served from `public/` directory
- API endpoints are unchanged and continue to work as before

## Rollback

To rollback to previous version:
```bash

git log --oneline | head -n 10  # Find previous commit

pm2 restart kotopes
```
